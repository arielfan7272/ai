# 工时记录（Time Tracker）— 律师使用说明

面向律师日常办案的桌面工具：维护可编辑待办清单、按项目计时，并可选根据 Gmail 邮件生成待办。界面支持 **中文 / 英文**。

---

## 功能概览

**工时记录** 可帮助您：

- 按项目（事项）维护**当日待办清单**
- 对所选项目进行**开始 / 结束**计时
- 查看当日**已完成工作**（用时 + 工作描述）
- 在日历中浏览**工时历史**
- 按您指定的日期范围，从 **Gmail** 生成中文或英文待办

适合需要简单、可追溯的每日工作记录，并供后续汇总或跟进使用的律师。

## 快速开始

1. 首次使用请安装依赖：

   ```bash
   pip install -r requirements.txt
   ```

2. 启动程序：

   ```bash
   python time_tracker.py
   ```

3. 可选参数：

   | 参数 | 作用 |
   |------|------|
   | `--lang en` 或 `--lang cn` | 强制本次启动的界面语言 |
   | `--date YYYY-MM-DD` | 将指定日期当作“今天”（便于测试） |

示例：

```bash
python time_tracker.py --lang cn
```

## 中英文界面

- 在首页和工时页使用 **EN / CN** 切换界面语言。
- 选择会保存在 `.time_logs/settings.json`。
- 从邮件生成待办时，可单独选择**待办语言**（EN 或 CN），与界面语言无关——例如界面用中文，生成的待办用英文，或相反。

## 每日使用流程

1. 打开 **工时记录**（首页显示当天日期）。
2. 点击 **开始工作！** / **Let's roll!**。
3. 在待办清单中选择一个项目。
4. 点击 **开始** 计时；**结束** 停止；**清零** 清除该项目当日已记时间。
5. 收工后点击 **今日收工！** / **Off work today!**，查看当日汇总（项目名称、工作描述、用时）。
6. 如有需要，可在汇总页修改用时。
7. 点 **首页** 返回；点 **工时历史** 打开日历，查看过往日期。

同一时间只会有一个项目在计时；开始另一个项目时，会自动结束上一个。

---

## 可编辑待办清单

在工时页：

1. 点击 **编辑清单** / **Edit list**。
2. 使用 **添加项目**，或对某一行使用 **编辑** / **删除**。
3. 每个项目包含名称和若干待办事项（这些事项会成为工时记录中的**工作描述**）。
4. 点击 **保存清单** / **Save list** 写入本地文件。
5. 编辑完成且无未保存更改时，可点 **完成** / **Done** 退出编辑模式。

若带着未保存的修改离开工时页，程序会询问：保存、放弃或取消。

---

## 根据邮件生成待办

不必全部手打，可从 Gmail 生成或补充当日清单。

1. 在工时页（非编辑模式）点击 **根据邮件生成** / **From emails**。
2. 在对话框中设置：
   - **邮件日期范围** — 含首尾的 **开始** 与 **结束** 日期（格式 `YYYY-MM-DD`）。默认均为当前记工日期（例如 8 月 2 日）。
   - **待办语言** — 生成内容使用 **EN** 或 **CN**。
3. 点击 **生成** / **Generate**。
4. 等待程序完成：
   - 拉取该日期范围内的 Gmail  
   - 对邮件分类与摘要  
   - 按项目生成待办事项  
5. 结果会**合并**进当前清单：
   - 保留已有项目  
   - 同名项目 → 追加新的事项文本（完全相同的文本不会重复添加）  
   - 新项目名称 → 追加到清单末尾  
6. 请先核对清单，再点击 **保存清单**，以便写入当日文件。

**说明：** 生成**不会**整表覆盖您的清单。合并满意后务必保存。

### 使用邮件生成前需要准备

一次性配置（见下方 [首次配置](#首次配置)）：

- Google Gmail 授权（`credentials.json` + 浏览器登录 → 生成 `token.json`）
- 在 `.env` 中配置豆包 / Ark 密钥：`ARK_API_KEY`

若所选日期范围内没有邮件，或密钥 / 登录失败，会提示错误，**不会**清空您现有的待办清单。

## 工时历史

- 在首页打开 **工时历史** / **Time log history**。
- 已有工时记录的日期会在日历上高亮。
- 点击某一天可查看**工作记录**：项目名称、描述、用时。
- 可在该页调整用时；描述会随该条记录保留。

每日工时文件会记录项目名称、用时与工作描述（来自待办事项），便于日后查阅或进一步处理。

---

## 数据保存在哪里

所有数据保存在程序目录下的 **本机** 文件夹 `.time_logs/`：

| 路径 | 内容 |
|------|------|
| `.time_logs/todos/YYYY-MM-DD.json` | 当日待办清单（项目与事项） |
| `.time_logs/YYYY-MM-DD.json` | 当日工时（用时、计时状态、各项目描述） |
| `.time_logs/emails/` | 生成待办时拉取 / 处理后的邮件 JSON |
| `.time_logs/settings.json` | 界面语言偏好 |

备份时可直接复制整个 `.time_logs/` 文件夹。程序打开期间请勿随意改动这些文件（除非您熟悉其 JSON 格式）。

## 首次配置

### 1. Python 依赖包

```bash
pip install -r requirements.txt
```

### 2. Gmail（用于「根据邮件生成」）

1. 将 Google OAuth 桌面应用凭证保存为项目目录下的 `credentials.json`（或设置环境变量 `GMAIL_CREDENTIALS_PATH`）。
2. 首次拉取邮件时，浏览器会打开，请授权 **只读** 访问 Gmail。
3. 授权成功后会生成本地 `token.json`，供之后使用。若令牌过期或被撤销，程序会再次引导您登录。

可选环境变量：

- `GMAIL_CREDENTIALS_PATH` — 凭证文件路径  
- `GMAIL_TOKEN_PATH` — 令牌文件路径  
- 代理：`GMAIL_PROXY` / `HTTPS_PROXY` / `HTTP_PROXY`（如需要）；程序也会尝试检测常见本地代理端口（如 7890）

### 3. AI 密钥（用于邮件分类 / 摘要 / 生成待办）

在项目目录创建 `.env` 文件：

```env
ARK_API_KEY=请填写您的密钥
```

没有该密钥时，仍可手动编辑待办并正常计时；但无法使用 **根据邮件生成**。

## 隐私与安全

- 待办、工时与邮件缓存均保存在您电脑的 `.time_logs/` 中。
- Gmail 权限为**只读**（程序不会代发邮件）。
- **请勿**对外分享或提交：`credentials.json`、`token.json`、`.env`，以及含有客户邮件内容的 `.time_logs/` 副本。
- 上述敏感路径已写入 `.gitignore`，默认不会被 git 推送。
- 生成待办时，邮件内容会发送至所配置的 AI 模型（豆包 / Ark）。请仅在符合律所合规要求的前提下处理相关邮件。

## 常见问题

**界面语言又变回原来的了**  
再次用 EN/CN 切换即可；选择会写入 `.time_logs/settings.json`。

**「根据邮件生成」提示令牌无效**  
按提示在浏览器中重新登录，或删除 `token.json` 后重试以重新授权。

**所选日期范围内没有邮件**  
检查开始/结束日期格式（`YYYY-MM-DD`，且开始 ≤ 结束），并确认该时段确有邮件。可适当扩大日期范围再试。

**提示缺少 `ARK_API_KEY`**  
在 `.env` 中配置后重新启动程序。

**生成后关闭程序，事项不见了**  
生成后请点击 **保存清单**。未保存的合并结果不会写入待办文件。

**生成会不会清空我手写的项目？**  
不会。结果是**合并**：同名项目追加新事项，其他项目保留。

**生成之后还能改吗？**  
可以。使用 **编辑清单**，再 **保存清单**。

**不接邮箱能不能用？**  
可以。手动维护待办并计时即可；仅 **根据邮件生成** 需要 Gmail 与 AI 密钥。

**访问 Gmail 有网络 / 代理问题**  
若平时访问 Google 需要 VPN 或本地代理，请先开启。程序会使用环境变量中的代理设置，或自动检测本机常见代理端口。
